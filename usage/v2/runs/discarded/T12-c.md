# Suppressing a GritQL plugin lint rule in Biome

## Syntax

```js
// biome-ignore lint/plugin/<plugin-name>: <explanation>
```

`<plugin-name>` is the plugin's file name without the `.grit` extension [doc]. So a plugin defined
in `preferObjectSpread.grit` is suppressed with:

```js
// biome-ignore lint/plugin/preferObjectSpread: reason
Object.assign({}, foo);
```

This disables diagnostics from that one plugin for the next line [doc].

## How this differs from a built-in rule

For a built-in rule you address it by its group and rule name, e.g. `lint/suspicious/noDebugger`
[doc]. Plugin diagnostics don't have that group/rule-name pair — they all live under a single
fixed group, `plugin`, with the plugin's file-derived name taking the slot a rule name would
normally occupy [doc]:

```js
// built-in rule
// biome-ignore lint/suspicious/noDebugger: reason
debugger;

// GritQL plugin rule
// biome-ignore lint/plugin/preferObjectSpread: reason
Object.assign({}, foo);
```

## Suppressing all plugins at once

Omit the plugin name and stop at the `plugin` group to silence diagnostics from every plugin on
the next line [doc]:

```js
// biome-ignore lint/plugin: reason
```

## General suppression-comment shape (for reference)

`biome-ignore` (and its `biome-ignore-all` / `biome-ignore-start` / `biome-ignore-end` variants)
is followed by a category (`lint`, `assist`, or `syntax`), then an optional group, or group/name,
separated by slashes — the more specific, the narrower the suppression — then a required
`: <explanation>` [doc]. For plugins, `plugin` is the group and the `.grit` file's base name is
the "name" segment [doc]. The docs only show plugin targeting with the plain inline `biome-ignore`
form above; they don't give a combined example with `-all`/`-start`/`-end`, though the category
segment itself is shared syntax across all four prefixes [doc].
